# Proposal

## Why

The backend foundation is done, but the ERP has no UI. Frontend features will be delivered through separate PRDs, so they need a shared Angular foundation first: project setup, conventions, and one working reference feature wired to the backend Todo API.

## What Changes

- Create the Angular application (latest stable, standalone, TypeScript strict) directly in `frontend/`, with `package.json` at `frontend/` root and no nested app folder (FR-016).
- Add Spartan UI (Tailwind CSS v4, Spartan `brain` primitives, CLI-generated `helm` components, Lucide icons through ng-icons) with a default theme.
- Use Roboto as the application font, self-hosted with the app.
- Add routing with lazy-loaded features and routes for Home and Todo. No menus, shell, dashboard or guards.
- Add a minimal Home page that confirms the app loads.
- Add `FeatureTemplate` with the Todo reference feature: list, create, edit, delete, using Reactive Forms, a Spartan table, and a signal-based feature service.
- Add API integration: `HttpClient`, configurable API base URL, and feature services as the only code that calls the backend.
- Add small HTTP interceptors (API base URL and error handling); no authentication.
- Add Spartan (Sonner) notifications and centralized HTTP/API error handling, including backend validation errors.
- Add a `shared` area for UI components, populated only where reuse is real.
- Add frontend unit/component tests for the Todo feature.
- Write `kb/architecture/frontend.md` describing the implemented design.

Out of scope (future PRDs): application shell, dashboard, navigation menus, auth, user management, multi-company, route guards, localization, end-to-end tests, error monitoring, CI/CD.

Assumptions:
- The backend Todo API is the one built in `backend-foundation`: `GET/POST /api/todos`, `GET/DELETE /api/todos/{id}`, with RFC 7807 problem-details errors. The backend returns all todos unpaged, so pagination, sorting and search are client-side.
- "View Todo where required" (FR-006) needs no separate page: the edit form shows a todo's full details, so there is no read-only view screen.
- The backend has no CORS configuration, and this change does not edit the backend. In development the Angular dev server proxies `/api` to the backend, so the browser sees one origin. Production hosting and CORS are deployment concerns for a later PRD.
- Angular's default test runner is used.
- UI library: Spartan UI replaced PrimeNG during implementation. PrimeNG 22 (PrimeUI) requires a license key and shows a banner without one; Spartan is MIT with no key. The component source generated by the Spartan CLI lives in `frontend/src/app/shared/ui` and is owned by the project.
- `FR-016` is read as "the project lives directly in `frontend/`", not in a subfolder such as `frontend/erp-web`.

## Capabilities

### New Capabilities
- `frontend-app-foundation`: Angular app setup, routing, Home page, Spartan UI theme, API base URL and HTTP integration, interceptors, feature-based structure and shared area.
- `frontend-todo-feature`: the FeatureTemplate Todo list, create, edit and delete screens, forms, table behavior and state handling.
- `frontend-error-handling`: user notifications and centralized handling of HTTP, validation, network and unexpected errors.
- `frontend-testing`: required automated test coverage for the Todo feature.
- `frontend-architecture-docs`: content requirements for `kb/architecture/frontend.md`.

## Impact

- New code under `frontend/` only, plus new `kb/architecture/frontend.md`. The backend is not modified.
- New dependencies: Angular, Tailwind CSS v4, Spartan UI (`@spartan-ng/brain`, `@spartan-ng/cli` as a dev tool), Angular CDK, ng-icons (Lucide), `clsx`, `tw-animate-css`, `@fontsource/roboto` (Roboto font files, OFL), RxJS (via Angular), and the Angular test tooling. All MIT or similar open licenses with no license key. No NgRx.
- Needs the backend running with an Oracle connection to use the Todo screens end to end.
- Requires Node.js (v24 is installed) and npm.
