# Proposal

## Why

The backend foundation is done, but the ERP has no UI. Frontend features will be delivered through separate PRDs, so they need a shared Angular foundation first: project setup, conventions and the shared infrastructure every feature uses (API access, errors, notifications, theme).

The Todo reference feature that originally accompanied this foundation has been moved out. It will get its own PRD, so this foundation ships the infrastructure and the conventions, without a demonstration feature.

## What Changes

- Create the Angular application (latest stable, standalone, TypeScript strict) directly in `frontend/`, with `package.json` at `frontend/` root and no nested app folder (FR-016).
- Add Spartan UI (Tailwind CSS v4, Spartan `brain` primitives, CLI-generated `helm` components, Lucide icons through ng-icons) with a default theme.
- Use Roboto as the application font, self-hosted with the app.
- Add routing that supports lazy-loaded features, with a route for Home. No menus, shell, dashboard or guards.
- Add a minimal Home page that confirms the app loads.
- Add API integration: `HttpClient`, configurable API base URL, and the rule that feature services are the only code that calls the backend.
- Add small HTTP interceptors (API base URL and error handling); no authentication.
- Add Spartan (Sonner) notifications and centralized HTTP/API error handling, including passing backend validation errors to the caller.
- Add a `shared` area for UI components, populated only where reuse is real.
- Add frontend tests for the core infrastructure (error mapping, interceptors).
- Write `kb/architecture/frontend.md` describing the implemented design and the conventions the next feature should follow.
- **Removed from this change:** the Todo reference feature (list, form, delete, state, tests) and the `frontend-todo-feature` spec. The code is removed in the apply step of this change.

Out of scope (future PRDs): the Todo feature, application shell, dashboard, navigation menus, auth, user management, multi-company, route guards, localization, end-to-end tests, error monitoring, CI/CD.

Assumptions:
- The backend (archived `backend-foundation`) returns RFC 7807 problem-details errors, and validation failures are 400 with an `errors` map keyed by property name. The error handling is built for that shape and is tested without a backend.
- The backend has no CORS configuration, and this change does not edit the backend. In development the Angular dev server proxies `/api` to the backend, so the browser sees one origin. Production hosting and CORS are deployment concerns for a later PRD.
- Angular's default test runner is used.
- UI library: Spartan UI replaced PrimeNG during implementation. PrimeNG 22 (PrimeUI) requires a license key and shows a banner without one; Spartan is MIT with no key. The component source generated by the Spartan CLI lives in `frontend/src/app/shared/ui` and is owned by the project.
- `FR-016` is read as "the project lives directly in `frontend/`", not in a subfolder such as `frontend/erp-web`.
- Conventions for forms, data tables and feature state (typed Reactive Forms, signal-based feature services, client-side paging) are documented as guidance for the next feature. They are not demonstrated in code until a feature PRD needs them.

## Capabilities

### New Capabilities
- `frontend-app-foundation`: Angular app setup, routing, Home page, Spartan UI theme, font, API base URL and HTTP integration, interceptors, feature-based structure and shared area.
- `frontend-error-handling`: user notifications and centralized handling of HTTP, validation, network and unexpected errors.
- `frontend-testing`: required automated test coverage for the core infrastructure.
- `frontend-architecture-docs`: content requirements for `kb/architecture/frontend.md`.

### Modified Capabilities
<!-- None. The backend specs are archived and unchanged. -->

## Impact

- New code under `frontend/` only, plus new `kb/architecture/frontend.md`. The backend is not modified by this change.
- New dependencies: Angular, Tailwind CSS v4, Spartan UI (`@spartan-ng/brain`, `@spartan-ng/cli` as a dev tool), Angular CDK, ng-icons (Lucide), `clsx`, `tw-animate-css`, `@fontsource/roboto` (Roboto font files, OFL), RxJS (via Angular), and the Angular test tooling. All MIT or similar open licenses with no license key. No NgRx.
- The app runs without the backend; backend connectivity is exercised once a feature calls it.
- Requires Node.js (v24 is installed) and npm.
